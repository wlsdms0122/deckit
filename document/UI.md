# The kit (`shell.ui`)

Every page deckit's shell draws, a mod's and its own, draws with one kit, so the desktop looks like one app. The kit is deckit's shell's, which hands it to every mod: `shell.theme` is the look; `shell.ui` is the parts drawn in it. How to use them so a view fits with the rest is in [GUIDELINES.md](GUIDELINES.md).

The kit's parts are of five kinds:

- A maker takes one options object and returns `{ element, ...its controls }`. Put `element` where it goes; call the controls to change it.
- A presentation takes one options object, is presented over the page on a layer and returns `{ close }`: `modal`, `dialog`, `confirmTrash`, `colorPicker`. `menu`, `popover` and `quickPick` are presentations too, with more controls. What a key opens or closes comes and goes at once; what the pointer opens fades and scales in from where it hangs.
- A float its caller places stays in the document of the text it acts on, so the keyboard stays with that text: `floatingToolbar`, `autocomplete`.
- A decorator takes `(element, options)` and returns its dispose. `listbox` decorates an element and returns its controls with `dispose` among them; `inlineEdit` is one edit and resolves when it ends.
- A helper returns a value: markup, an element, a colour, a boolean, a function or a list.

A control draws the value it is set to and reports what was asked (`onChange(next)`); its caller keeps the value and calls `set(next)`. A callback that reports what happened is `on` and a verb (`onChange`, `onPick`); one the kit asks for something is named for what it gives (`create`, `placeAt`, `describe`) or does (`run`). A control's size is `'small'` or `'medium'`; a glyph's size (`icon`, `spinner`, `folderIcon`) is in px.

## The theme

`shell.theme` is derived from the host app's colours and the person's fonts (MOD.md, `shell.fonts`), and changes when the host app gives new colours or the person new fonts. Each key is read as it is now; `theme.onChange(listener)` hears a new theme and answers its off.

| Key | What it holds |
|---|---|
| `dark` | whether the background is dark |
| `font` | the family the app's own parts are in, the host app's |
| `textFont` | the family a page's text is in where nothing chooses another, and text a person reads and writes: the person's face, falling back to `font` |
| `mono` | the fixed-width family: the system's |
| `textSize` | the size in px of that text: the person's, 14 by default |
| `fonts` | what the person chose, `{ text, size }`: a face's name and a size in px, each null for the default |
| `type` | font shorthands, each with its line height: `caption` 11/1.35, `small` 12/1.4, `body` 13/1.45, `large` 15/1.4, `heading` 17/1.3, `title` 20/1.2; and `label` 12/1.4 at 600, what names a group or a column, drawn in `muted` in sentence case |
| `tracking` | `title`, -0.01em, the letter spacing the title step is drawn with |
| `border` | the border shorthand |
| `color` | `text`, `muted`, `disabled`, `placeholder`, `background`, `surface` and `lifted` (wells in the content), `elevated` (what floats over it: a menu, a popover, a dialog's card, a toast, the Dock), `thumb` (the chosen part of a control on a filled track, as a segmented control's, lifted off the track's `fill`), `sidebar`, `divider`, `fill`, `hover`, `selected`, `pressed`, `accent` (text and glyphs), `accentFill` (what is on or pressed first, with `onAccent` over it), `ok`, `warn`, `alert` (status as a dot or a wash) and `okInk`, `warnInk`, `alertInk` (status as text or a glyph), `focus`, `target`, `scrim` (what dims the page under a dialog, lighter in the light look), `folder` |
| `radius` | `small` 4, `control` 6, `medium` 8, `large` 10, `card` 12, `round` 999 |
| `appIcon` | the sizes in px an app icon is drawn at, one per role: `small` 16 (a menu, a bar, a sidebar heading), `row` 20 (a row, a notification), `lead` 32 (the top match, a mod's own head), `dock` 40, `grid` 56 (a launcher) |
| `rim` | the hairline inside a floating surface's edge, a `box-shadow` laid with `shadow.float`: stronger while the system asks for more contrast |
| `shadow` | `float`, what a floating surface casts; `control`, a knob's; `sidebar`, the sidebar card's; `key`, a window with the keyboard, and `inactive`, a window without it, each per look with the window's ring; `lifted`, a row lifted to move; `drawer`, what lies along an edge over the content; `icon`, a `filter` laid under an app icon drawn at 32px and up |
| `motion` | `move.fast`, `move.base`, `move.slow` in ms for what moves or changes size, 0 while the system asks for reduced motion; `fade` in ms for what fades or changes colour, as long then too; `easing` for what comes and goes, `easingMove` for what moves from one place on screen to another; and `entrance`, the transform a surface arrives from as it comes on screen |
| `syntax` | the code palette: `keyword`, `string`, `number`, `comment`, `function`, `type`, `property`, `operator`, `meta`, `invalid` |
| `glass` | the strength a surface drawn as glass lays its colour at over what is behind it, blurred through: 0.72 light, 0.85 dark, and 1 while the system asks for less transparency or more contrast |
| `blur` | the material a floating part in a page lays over what is behind it, `blur(24px) saturate(1.6)`, and `none` while the system asks for less transparency or more contrast |

For CSS, the token is also custom properties on the page's root: each colour by its name in kebab case (`--deckit-muted`, `--deckit-on-accent`), `--deckit-type-*`, `--deckit-tracking-title`, `--deckit-radius-*` in px, `--deckit-app-icon-*` in px, `--deckit-rim`, `--deckit-shadow-*`, `--deckit-glass` as a percentage, `--deckit-blur`, `--deckit-move-fast`, `--deckit-move-base`, `--deckit-move-slow` and `--deckit-fade` in ms, `--deckit-easing`, `--deckit-easing-move`, `--deckit-font`, `--deckit-mono`, `--deckit-text-font`, `--deckit-text-size` in px and `--deckit-border`. `dark`, `syntax` and `entrance` are read from `theme`. A new theme changes the custom properties and the page's `color-scheme` in place, so whatever is drawn with them (and CSS `light-dark()`) follows by itself; what a mod worked out from `theme` in code it works out again in `onChange`. A mod adds rules of its own with `ui.addStyle(css)`, which its windows wear too, added before or after they open; its class names start with its id. A mod with `deckit.styles` styles other pages with the same names (MOD.md, `shell.styles.register`).

## Buttons

A control is `size: 'medium'`, 32px tall, or `'small'`, 24px: an icon button, a text button, a segmented control, a field, a stepper and a select alike, so controls side by side line up. What is smaller (a row's action, a stepper's buttons) is pressed in a 24px square all the same.

- `iconButton({ icon, title, size, muted, onClick })` returns `{ element, setPressed(on), setEnabled(on), setIcon(svg) }`. `muted` rests it a step back until the pointer comes. A button turned off with `setEnabled(false)` keeps the pointer and its tooltip and does nothing when pressed (`aria-disabled`).
- `button({ label, title, icon, size, variant, onClick })` returns `{ element, setLabel(text), setEnabled(on) }`. `variant` is `plain`, `primary` or `destructive`.
- `rowAction({ icon | label, title, onClick })` returns `{ element }`: an action of a row, shown while the row is hovered or holds the focus, and taking no room while it is hidden. An element that is no `ui.row` shows its actions the same way when it carries `data-deckit-row-actions`, and keeps them shown while that is `shown`; outside both they always show. Its click is its own.
- `segmented({ items, value, size, accent, fill, onChange })` returns `{ element, set(key), setItems(items), elementOf(key) }`. `items` are `{ key, label, title, lead }`; with `fill` the choices share the width it is given. The choices sit on a filled track, the chosen one lifted on `thumb`.
- `toggleButton({ icon | label, title, value, onChange })` returns `{ element, set(on), setMarked(on) }`: on or off beside a field that keeps the keyboard.
- `toggle({ value, onChange })` returns `{ element, set(on), setEnabled(on) }`: a switch.
- `tooltip(element, { text, chord })` is a decorator: `chord()` is read as the pointer comes, so a key the person changes shows.

## Text and numbers

- `field({ placeholder, value, icon, inline, trailing, size, clearable, onInput, onSubmit, onCancel })` returns `{ element, input, set(value), focus() }`. Enter calls `onSubmit(value, { shift })`; Escape is the field's only when `onCancel` takes it.
- `stepper({ value, min, max, step, unit, unset, size, onChange })` returns `{ element, set(value) }`. Enter and leaving the field report what is typed; Escape puts the value back. With `unset`, `{ label, value }`, it may hold no number, null: it shows `label` then and steps from `value`, and what is typed cleared reports null.
- `findBar({ placeholder, options, nav, replace, onChange, onNext, onPrevious, onCancel })` returns `{ element, setQuery(text, options), focus(which), setCount(active, total), setReplaceOpen(on), state(), replacement() }`. `options` are any of `caseSensitive`, `word`, `regex`, and `state()` is `{ query, caseSensitive, word, regex }`, what `onChange` gets too; `setQuery` takes the same keys. `focus(which)` puts the keyboard in the find field, or with `'replace'` in the replace field. `replace` is `{ open, onReplace, onReplaceAll }`: `onReplaceAll` is required, and without `onReplace` there is no Replace button and Enter in the replace field replaces all.

## Layers and what is presented

A page's layers are drawn in its overlay: a document beside the page, laid over it while a layer draws anything, over everything else on screen with the page, its web pages too. Each layer is over the page and the layers added before it. The overlay takes presses where a layer draws what takes them, and has the keyboard while an element in a layer holds the focus.

- `layer(element)` returns `{ element, focus(target), remove() }`: `element` on a new layer, over the page and its web pages. Its caller places it with `position: fixed` and `top`, `left`, `right` or `bottom`, in the page's coordinates, and plays its own entrance and exit. It takes presses only where it lies, so the page around it goes on as it is, as the Browser's find bar does. `focus(target)` gives `target`, `element` unless given, an element or a control with `focus()`, the focus and the keyboard the page has, as a press in it does. `remove()` takes it away.

What is presented over the page is on layers, in one stack. The top one has the keys first; Escape and a press outside put it away, then the next, until one holds the press. It lies on a backdrop that takes every press over the page while anything is presented, so a press outside is theirs and goes no further. Each has the focus and the keyboard as it opens, and gives them back as it closes. What a drag carries is drawn on a layer too.

- `menu({ items, anchor | point, onClose })` returns `{ element, close(), isOpen() }`, or null when a second press on its anchor closed it. An item is `'-'` (a separator) or `{ label, icon, hint, checked, disabled, items, font, run }`; `items` makes a submenu. When any item has an icon, every row keeps the icon's room, so the labels start in one column. Every row is 28px. A menu is as tall as the room on its side of what opened it, 16px inside the window and 480px at most, and scrolls inside past that; it opens above where it does not fit below, the room there is under 160px and the room above is larger, and its chosen row is scrolled into view. A menu that grows once placed, as its rows wear their faces, is placed again. Arrow keys move, Enter or Space takes, Tab and Escape close.
- `select({ options, value, size, onChange })` returns `{ element, set(value), setOptions(options) }`: a pop-up button. `options` are `{ value, label, font, icon, hint }`, drawn as a menu's items are; the chosen one's icon stands before its label on the button.
- `contextMenu(area, { rowAt, items, keyRow })` is a decorator: the context click, the ContextMenu key or Shift+F10 opens `items(row)` for the row under the pointer or with the focus, and the row is marked while it is open.
- `popover({ width, onClose })` returns `{ element, show(anchor), close(), isOpen() }`. `width` is the widest it grows to.
- `modal({ title, confirmLabel, cancelLabel, destructive, extraLabel, onExtra, chrome, align, drags, clear, glass, width, fill, onKey, onConfirm, onClose })` returns `{ close }`. `fill(card)` puts the content in and returns what takes the focus. With `chrome`, a title and the buttons; Enter in a text field confirms, and a button alone is the default one, filled, which Enter takes. `align` is `center`, `top`, or `fill`, the card all the page draws, filling it, its edge the page's, which comes and goes at once, as its window does. With `drags` the card drags the window it is in where nothing in it is pressed. With `clear` the page shows through undimmed, the card still holding every press, and it comes and goes at once, as a palette does. With `glass`, a strength from 0 to 1, the card's colour is laid at it, for a page over something that blurs what is behind it. `onKey(event)` has a key first and answers true when it took it; a key it does not take goes on to Enter and Escape as well.
- `dialog({ title, message, content, fields, confirmLabel, cancelLabel, extraLabel, onExtra, destructive, onConfirm, onClose })` returns `{ close }`: a modal that says something and asks for values. `message` is a paragraph, or a list of them. `fields` are `{ key, label, type, value, placeholder, options }`, a text field unless `type` is `switch` or `color`. A label of null leaves its button out, so a dialog that only tells has OK alone. `onConfirm(values)`.
- `confirmTrash({ name, onConfirm })`: asks before a folder and what is in it go to the Trash.
- `colorPicker({ title, value, onPick })`.
- `quickPick({ placeholder, value, fills, drags, glass, width, key, create, update, optionOf, onInput, onPick, onEnter, onKey, onActive, onCommandKey, onHeight, onClose })` returns `{ text(), setText(text), setPlaceholder(text), setScope({ icon, appIcon, label } | null), focus(), set(items, { active, message, note, loading, alert }), move(by), active(), close() }`: a field over a list to pick from, at the top of the page, on a `clear` modal, so it neither dims the page nor moves as it comes and goes, or with `fills` on one that fills the page (`align: 'fill'`), and with `drags` it drags the window from anywhere but its list, the field too, which keeps the keyboard all the same; `glass` is the modal's. A quick pick that fills an overlay window's page drags it and is drawn at `glass: theme.glass`; with `fills`, `onHeight(px)` hears the height its content takes with every row shown, as it changes, for the window to fit it. Items are drawn by `key(item)`, `create` and `update`, as a keyed list draws them; `optionOf(item)` is null for an item that is no option (a heading) or `{ disabled }`. The arrows move the active option, which `onActive(item, index, { pointer })` hears, and Enter picks it, which `onPick(item, index)` hears, or `onEnter({ item, text })` hears both. `onKey(event)` has a key first and answers true when it took it, or the arrows, Enter and Escape act on it too; `onCommandKey(held)` hears Command held down or let go. The field keeps the focus. `setScope` shows what the field searches in, before it: `icon` an app icon at 16 where `appIcon` is true, else SVG markup.

A toast tells what was just done, or that it failed, where it was done and nothing else in the view holds the result.

- `toast(text, { kind, action })` returns `{ close() }`: `text` at the bottom right of the page, clear of its title bar and what heads its content, on a layer over the page, wrapping anywhere a long word or path would run out. By default it stays a few seconds, longer for more words, and takes no presses. With `kind: 'failure'` it is read out as an alert, takes presses and stays until the person closes it with the close button beside its text, and `action`, `{ label, run }`, adds the one button that acts on the failure (Try Again, Choose Another Folder...), on a row of its own under the text at its end, which closes it too. Toasts stack, the newest nearest the edge, four at most; one that stays may cover the last rows of the content until it is closed.

Floats are placed by their caller and stay in the page, where the keyboard stays with the text they act on.

- `floatingToolbar({ over })` returns `{ element, show(rect), hide() }`: centred above the rect, below when only that fits, in the document `over` is in as it shows, the element whose text it acts on (the page's own without it).
- `autocomplete({ onPick, over })`, in the document `over` is in as `floatingToolbar` is, returns `{ show(items, rect), place(rect), move(by), pick(), close(), isOpen() }`. An item is `{ label, icon, hint }`, and `onPick(item)` gets it. The caller moves through it with its own keys.

## Lists

- `list({ key, create, update, animated, maxRows, size })` returns `{ element, set(items), elementOf(key), keyOf(element) }`. Rows are drawn by `key(item)`: the same key keeps the same element, so what the pointer rests on and what has the focus stay put. `create(item)` makes a row; `update(element, item)` refreshes a kept one. A key names one item: a key given twice throws. With `animated`, a row added once the list has shown items fades in; a removed one leaves at once, and the rows after it close up. While something in or around the list is held (dragged, renamed), a new set waits and the last one is drawn when it is let go. With `maxRows`, the list is at most that many rows tall and scrolls.
- `row({ size })` returns `{ element, setActive(on), setActionsShown(on) }`: body text, washed under the pointer; `setActive` marks it chosen, `setActionsShown` keeps its actions shown.
- `listbox(element, { onPick, onActivate })` returns `{ set(options, { active }), move(by), activate(index), active(), dispose() }`: one active option among `options` (`{ element, disabled }`), moved by the keys and by a pointer that travels, picked by a press. `onActivate(index, { pointer })` hears the active option change and `onPick(index, { keyboard })` a pick; the active option is marked `data-active`.
- `tree(element, { items, lead, nameOf, multiple, expanded, parentOf, childrenOf, onSelect, onSelectAll, onToggle, onPreview, onRename, onOpen })` is a decorator: the keys of a list or a tree of items the person selects, as ARIA's tree and listbox patterns have them. It is named for ARIA's tree, items the person selects that may nest, so a list whose items do not nest is a tree of one level. It is not `listbox`, one active option that the keys and the pointer move and a press picks (a menu's, a quick pick's), with no selection kept; and `treeRow` draws a row of a tree, with no keys. `element` takes the focus and the keys pressed on it; a key typed into something inside it (a rename) is that one's. The caller keeps the selection: `items()` are the keys of the items the arrows move among, in order, and `lead()` is the one they move from, or null. Up and Down go to the item before or after, and Option with them, Home and End to the first or the last: each calls `onSelect(key, { extend })`, and with `multiple`, Shift with any of them asks to `extend` the selection from its anchor to that item. Letters typed close together, a Space among them, go to the first item whose name, `nameOf(key)`, starts with them, Shift or not: `onSelect(key, { extend: false })`. With `multiple`, Command-A calls `onSelectAll()`. In a tree, `expanded(key)` is true, false, or null for an item that does not fold: Right unfolds a folded item (`onToggle(key, true)`) or goes to the first of `childrenOf(key)`, keys or a promise of them, and Left folds an unfolded item (`onToggle(key, false)`) or goes to `parentOf(key)`. Space, while no name is being typed, calls `onPreview(key)`, Return `onRename(key)`, and Control-Return `onOpen(key)`, for the lead; a key whose callback is not given is not taken, but for Space, which would scroll the list. These are the list's own keys, as Command-A is a text field's: the keymap does not list them and the person does not rebind them. A mod that offers one as an action of its own binds it with `deckit.keys.register`, as a mod binds Open to Control-Return, and a chord the mod binds is the mod's before the list hears it, so the person's binding holds.

## Sections and paths

- `section({ label, icon, actions, collapsed, onToggle, title, onHeading, onHeadingMenu, headingTitle })` returns `{ element, body, heading, actions, setCurrent(on), setCollapsed(on), isCollapsed() }`. With `collapsed` a boolean the heading folds the body: a press calls `onToggle(next)`, and the caller folds it; the body grows from nothing or folds away along its height, longer the taller it is. `actions` are `{ icon, title, run(button) }`. The label is 13px 600 in `muted`, never larger than the window's title; with `title` it is the view's own title, 17px 600 in `text`.
- `breadcrumb({ onGo })` returns `{ element, set(parts), partAt(element) }`; `partAt` answers the part an element is in, `{ key, element }`, or null. `parts` are `{ key, label, title, current, icon }`; what does not fit folds into a menu. In a title bar the current part is the view's title, drawn as `titleBar`'s title is, 17px 600.

## Files and folders

- `folderIcon({ open, size })`: a folder's icon, in the folder colour.
- `treeRow({ depth, folder, folds, open, glyph, name, size })` returns `{ element, setActive(on), setActionsShown(on), setOpen(open) }`. Its name is marked `data-name`, what a rename types over.
- `inlineEdit(label, { selectStem, onCommit })` renames a label in place, the field holding its text; `onCommit(text)` answers nothing or why it refused. An emptied field gives up, as Escape does. Resolves whether it renamed.
- `movesInto(from, folder)`: whether a move changes anything and is possible.
- `folderDrop(zone, { kind, paths, folderAt, onDrop })` makes a tree a drop target of moves into folders, as `dropTarget` does: `paths(payload)` is a function that answers where the dragged things are, all in one folder, and `folderAt(element)` answers the folder under the pointer, `{ folder, mark }`, or null. A drop into a dragged folder, or into what it holds, is refused, and one into the folder they are already in stays.
- `treeFolderAt({ row, markOf, top, topMark })` makes a `folderAt` for a tree: `row(element)` answers the row an element is in, `{ path, folder, element }` with `folder` whether it is a folder's, or null; `markOf(folder)` is the element that lights for a folder; `top` is the folder a drop on no row goes into, and `topMark` what lights for it.

## Dragging and sizing

- `sortable(list, { onReorder, depth, movesInto, onMoveInto, describe })` decorates a keyed list and returns its dispose: the rows put in a new order by a drag. The rows move along the list's axis: down it, or across it when the list is laid out as a flex row, as a strip of tabs is; the box that scrolls the list along it scrolls at its edges. `onReorder(key, toKey)` hears that the item `key` goes where `toKey` is, and the caller draws the new order. With `depth: { indent, project(key, toKey, levels), descendants(key) }` the rows nest: a move across the axis asks for a level deeper or shallower for each `indent` px, to the nearest, `project` answers the depth the row would take there, the held row stands that far in, and `onReorder(key, toKey, depth)` hears a move to the same place at another depth too. `descendants(key)` answers the keys of the rows that go with the row `key`, a folder's: they are put away while it is held, so it never goes among them, and the caller draws them under it where it lands. With `movesInto(key, toKey)`, a row held over the middle half of a row it answers true for goes into that row rather than beside it, as a folded folder takes what is dropped on it: the row is marked while the held one is over it, and `onMoveInto(key, toKey)` hears the drop. With `describe(key)`, `{ kind, payload, text, icon }` as `dragSource` has it, or null for a row that stays in the list, a row held over a `dropTarget` of that kind that answers a place is carried as `dragSource` carries it, and is sorted again when it leaves it; held anywhere else, it is sorted, and past the list's ends it goes first or last. A row alone in its list is lifted only to be carried.
- `marquee(area, { listAt, selection, onSelect })` is a decorator: selection by a rectangle dragged in `area`. `listAt(element)` answers the keyed list a rectangle started there selects in, `{ list, ... }`, or null where none starts: where a press drags a row, a rectangle does not start. The rows the rectangle crosses are selected: with Shift held at the press they are added to those of that list already selected (`selection()`), with Command they are toggled in that selection, so a selected row it crosses is let go, and with neither they are selected alone. A click in the list but on none of its rows selects nothing; a press on a scroll bar is no click. `onSelect(keys, place, { click })` hears each change: the keys in the list's order, with what `listAt` answered, and `click` true for that click, false for a rectangle. The rectangle stays inside the box that scrolls the list, and scrolls it at its edges.
- `dragSource(area, { itemAt, describe })` is a decorator: `describe(item)` is `{ kind, payload, text, icon }`.
- `dropTarget(zone, { kind, placeAt, onDrop })` is a decorator, for a drag within the page (files dragged in from outside the app come to `shell.dropDestination`, MOD.md): `placeAt(element, payload)` answers the place under the pointer, `{ mark, stays }`, or null where nothing lands. `mark` is the element that lights while the thing is over it, and a place that `stays` is where the thing already is, so a drop there drops nothing. `onDrop(payload, place)` takes any other.
- `resizer(handle, { axis, grow, size, min, max, onResize, onCommit, onClick, onDrag, resizable })` is a decorator: `axis` is `x` or `y`, and `grow` is how much the size changes for each px the pointer moves along it, `1` by default and `-1` for a handle at the start of what it sizes. `size()` reads the size, `onResize(px)` draws one, `onCommit(px)` keeps the one let go of. `min` and `max` are numbers, or functions read at the press. Past a limit the edge gives and springs back; a press that does not travel is a click, `onClick`. `onDrag(on)` hears a drag start and end, and `resizable()`, read at the press, says whether a drag sizes at all.

## Split view

- `splitView({ sidebar, content, width, collapsed, onChange })` returns `{ element, isCollapsed(), setCollapsed(collapsed), toggleSidebar(), width() }`: a sidebar beside the content, put in a window's content (MOD.md, `shell.windows.open`) or a part of it. `sidebar` is drawn in a card on the sidebar's material at the start, scrolls when it is taller than the card and lists from under the window's buttons; `content` takes the rest, and its title bar (`titleBar`) clears the buttons only while the sidebar is folded. Where the split view draws nothing, the window's background material shows through. The divider's handle stands in the gap between the card and the content, its grip shown only under the pointer, while the keyboard is on it and during a drag; it sizes the sidebar by a drag, from 240 to 720 px and leaving the content 360, and folds or unfolds it by a click. A click of the pointer slides the card out of the window or into it with the content beside it; Enter or Space on the handle, and `setCollapsed` and `toggleSidebar`, as a key does, fold it at once. `width` and `collapsed` are how it starts; `onChange({ width, collapsed })` hears each change the person makes, for the mod to keep.

## Everything else

- `emptyState({ icon, title, hint, actions })` returns `{ element, set({ title, hint, actions }) }`.
- `notice({ kind, text, details, action })` returns `{ element, set(options) }`: what went wrong (`kind: 'failure'`, read out as an alert) or what to look out for (`'warning'`), shown where the result would be. A tinted well with no border, the `info` glyph in the tone's ink, `text`, the raw `details` behind a Details disclosure in small mono, and `action`, `{ label, run }`, a small button under the text.
- `spinner({ size })` returns `{ element }`. `loading({ text })` returns `{ element, settled() }`: it shows only once the load has taken 200ms, and `settled()` answers once it may be taken away, at once if it never showed or once it has shown 400ms, so it never flashes. `loading.skeleton({ rows, height })` returns the same for a list whose shape is known: `rows` rows `height` px tall, each a still 12px bar in `fill`, 60%, 40% and 75% wide in turn, with no shimmer; a spinner stays for a button or a row's icon slot.
- `icon(name, { size, fill, color, stroke })`: one of the kit's icons (Lucide), as SVG markup. A name it does not have throws. `iconOf(shapes, { size, fill, color, stroke })` draws shapes of the mod's own in the same frame. `sanitizeIcon(svg)` is an icon another mod gave, as an `<svg>` element rebuilt from its shapes alone, so nothing in the text runs, loads or styles the page, and no bigger than 24 by 24, its shape kept: what a mod draws of another's icon goes through it.
- `appIcon(icon, { size, alt })` returns an `<img>`: a mod's app icon, `icon` the text `shell.mods.list()` or `icon(id)` answers, drawn as an image at the `appIcon` size `size` names (`row` by default), or the default icon where `icon` is empty. `alt` is the mod's name where nothing beside the icon names it, and empty where a visible name does. At 32 and up it stands on `shadow.icon`. Pressed, a surface sets `filter: var(--deckit-shadow-icon) brightness(.85)` on it; hover and focus belong to the row or cell around it.
- `element(tag, { className, style, text })`.
- `edgeFade(element, { size })`, `pressable(element)`, `selectable(element)`, `titleBar(element, { title, scroller, hairline })` are decorators: the edges of what scrolls fade, and what is scrolled into view lands clear of the fade (its size the box's `scroll-padding`), something pressed is washed and ringed, text can be selected, and a bar along the top of the view lies in the window's title bar area (MOD.md, `shell.view.register`): 48px tall, as the window's title bar is, or as tall as the area where that is taller, what it holds in a row (padding 0 12px, gap 4px) centred on the window's buttons and clear of them, and dragging the window wherever nothing in it is pressed. Buttons, fields, links and anything with a `tabindex` in it take presses; another control there marks itself `--app-region: no-drag`. `title` puts the view's title first, 17px 600; `scroller` is what scrolls under the bar, whose edges fade where there is more of it; `hairline` draws a 1px `divider` rule under the bar instead, for content the fade cannot reach, as a web page. While the page's root carries `data-deckit-key="false"`, its window is not the key one: the bar's text and glyphs go to `muted`, a breadcrumb's current part with them, while a control turned off keeps its own look; and a chosen row or section heading goes to `fill`. The shell sets the mark on a window's content; a page without it draws as the key window's.
- `isFullyVisible(element)`, `capturePointer(cursor)` (returns the release), `mix(foreground, background, amount)`, `alpha(color, amount)`, `onColor(color)`: white or a near black, whichever reads better over a colour of the content's own (a calendar's).
- `installedFonts(faces)`: the faces (`{ font }`) installed on this Mac. `textFonts()` and `monospacedFonts()`: every font family installed on this Mac, and those whose faces are fixed-width, as options `{ value, label, font }`, the first `{ value: 'default', label: 'Default' }`, which leaves the face to the theme. A key of a mod's `form` names either as its `choices` (MOD.md, Configuration).
